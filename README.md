## 1. Призначення та функціональні межі системи

**VoluntHub** — серверний вебзастосунок на базі **Java 21** і **Spring Boot 3.4**, призначений для впорядкування взаємодії між волонтерами та координаторами громадських, екологічних і освітніх ініціатив.

### Реалізоване функціональне ядро та погоджене ускладнення
- **Публічний каталог завдань (`Гість`, `Волонтер`, `Координатор`):** пошук за назвою та описом, фільтрація за містом, форматом участі (`ONSITE`, `REMOTE`, `HYBRID`), терміновістю (`NORMAL`, `HIGH`, `CRITICAL`), потрібною навичкою та наявністю вільних місць, посторінковий перегляд (пагінація) і коректне відображення порожньої вибірки.
- **Багатокритеріальний підбір завдань за навичками з генерацією пояснення рекомендації (погоджене ускладнення):** обчислення індексу відповідності $S(v, t) \in [0; 100]$ з урахуванням рівня володіння навичками ($1..3$), штрафного множника при відсутності обов'язкової навички, територіальної сумісності й пріоритетності, а також побудова розгорнутого текстового обґрунтування для користувача.
- **Керування заявками та атомарний контроль ліміту місць:** подання й скасування заявки волонтером, погодження або вмотивоване відхилення координатором із песимістичним блокуванням рядка завдання (`SELECT ... FOR UPDATE`) та частковим унікальним індексом активної участі у СКБД PostgreSQL.
- **Політика видимості контактних даних (`ContactVisibilityPolicy`):** телефон, електронна пошта й Telegram волонтера приховані у публічному каталозі та REST API для сторонніх користувачів і розкриваються виключно самому власнику або відповідальному координатору ініціативи за активною заявкою.
- **Підсумкове звітування та верифікація:** подання звіту з фактично витраченими годинами лише за власною погодженою заявкою, захист від редагування чужих або вже підтверджених звітів, перевірка координатором (`VERIFIED` / `NEEDS_REVISION`).

### Функції поза межами курсової роботи
- Приймання грошових пожертв і підключення платіжних шлюзів;
- Використання реальних чутливих локацій або персональних даних фізичних осіб (усі демонстраційні записи синтетичні);
- Зовнішня розсилка електронних листів або push-сповіщень поза навчальним середовищем.

## 2. Вимоги до програмного середовища

Перевірена конфігурація стенда:
- **ОС:** Windows 11 x64 (24H2) або Linux / macOS;
- **JDK:** OpenJDK / Oracle JDK **21 LTS** (перевірено на `21.0.12.1`);
- **Збирання:** Apache Maven **3.9+** (перевірено на `3.9.16`);
- **Контейнеризація СКБД:** Docker Engine **24+** і Docker Compose **v2+** (СКБД PostgreSQL `16-alpine` запускається виключно у контейнері без локального встановлення в ОС).

## 3. Швидкий запуск із чистого середовища

Усі команди нижче виконуються з кореневого каталогу проєкту `Ipatov_AI-243_CourseWork`.

### Крок 1. Конфігурація середовища
Файл `.env.example` містить усі параметри за замовчуванням для локального запуску. За потреби перевизначення портів скопіюйте його у `.env`:

```powershell
Copy-Item .env.example .env
```

### Крок 2. Запуск контейнера PostgreSQL 16 у Docker
```powershell
docker compose up -d postgres
docker compose ps
```
Контейнер `volunthub-postgres` піднімається на порту `127.0.0.1:5446` (проброс на `5432`), автоматично створює основну базу `volunthub` та тестову базу `volunthub_test` і проходить перевірку `pg_isready` (`healthy`).

### Крок 3. Збирання, міграції Flyway, завантаження seed-даних і запуск сервера
```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21.0.12.1"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
mvn spring-boot:run
```
Під час старту:
1. **Flyway** автоматично застосовує міграцію `src/main/resources/db/migration/V1__init_schema.sql` на порожній схемі;
2. **DemoDataSeeder** ідемпотентно завантажує синтетичний набір демонстраційних даних (12 навичок, 6 користувачів, 6 ініціатив, 15 завдань із нормальними й граничними станами, заявки та звіти); при повторному перезапуску дублікати не створюються;
3. Вебзастосунок стає доступним за адресою: `http://localhost:8096/tasks`
4. Специфікація контрактів **OpenAPI 3.1 / Swagger UI**: `http://localhost:8096/swagger-ui.html`
5. Перевірка готовності (**Readiness Probe**): `http://localhost:8096/actuator/health/readiness`

### Альтернативний повністю контейнеризований запуск (БД + застосунок у Docker)
```powershell
docker compose --profile full up --build -d
```

### Зупинка середовища
```powershell
# Зупинка зі збереженням постійного тому даних volunthub_pgdata:
docker compose down

# Повне очищення середовища разом із томом даних (УВАГА: видаляє всі записи БД):
docker compose down -v
```
